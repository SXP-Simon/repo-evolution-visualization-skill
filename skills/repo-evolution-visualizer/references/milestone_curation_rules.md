# 里程碑提炼与自然中文文案编写规范 (Milestone Curation Rules)

本文档说明如何从 Git 提交历史与 GitHub Release 中提炼真实、生动、通俗易懂的中文里程碑时间线。

---

## 1. 为什么拒绝生硬机翻与机械堆砌？

仓库演进可视化不仅仅是一堆数字的跳动，更是一部**开源社区与代码工程的成长史诗**。
- ❌ **糟糕的里程碑**：`feat: update regex parser and fix memory leak in handler.rs (#42)`（直接拷贝 commit 信息，生硬晦涩）；
- ✅ **优秀的里程碑**：`【性能飞跃】重构正则解析内核，告别大文件内存泄漏`（突出用户价值，语言自然亲切）。

---

## 2. 里程碑分类标签（Tag Taxonomies）

为便于视觉区分与色彩高亮，推荐使用以下 6 类标准化标签：

| 标签类别 | 推荐色系 | 触发场景范例 |
| :--- | :--- | :--- |
| **`项目诞生`** | 绿松石 (`#4ecdc4`) | 第一个 commit，仓库建立，核心原型问世 |
| **`重磅功能` / `功能上线`** | 珊瑚红 (`#ff6b6b`) | 核心新功能推出、重大特性发布（如上线每日漫画生成引擎） |
| **`社区里程碑`** | 明黄 (`#ffd93d`) | Star 突破 100/200/500/1000 颗、贡献者达 20 人等 |
| **`架构重构` / `体验优化`** | 绿松石 (`#4ecdc4`) | 底层解耦、大幅提速、移动端窄屏适配、深色模式等 |
| **`生态拓展` / `平台适配`** | 珊瑚红 (`#ff6b6b`) | 支持更多平台（如 Telegram、OneBot、Discord、QQ 官方机器人） |
| **`一周年/特别纪念`** | 明黄 (`#ffd93d`) | 开源一周年、两周年、大型峰会展示等 |

---

## 3. 自然文案编写要点

1. **标题控制在 15 ~ 25 字以内**：短小精悍，突出核心亮点；
2. **副标题/描述包含人物致谢与 PR 编号**：
   - 范例：`由 @clown145 贡献 Telegram 平台适配与内嵌按钮交互 (#82, #83)`；
   - 尊重每一位开源贡献者的辛勤付出，增强社区归属感与温度；
3. **语言风格**：
   - 亲切、自然、平实、富有朝气；
   - 严禁生硬机翻，严禁使用冷冰冰的机器代号；
   - 严禁在标题或卡片中夹带乱码或无意义 Emoji。
